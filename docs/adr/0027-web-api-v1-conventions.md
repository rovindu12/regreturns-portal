# 27. Web API v1 conventions: versions, OpenAPI, errors, paging, idempotency and rate limits

- Status: accepted
- Date: 2026-10-05

## Context

Bank systems integrate with the API once and then run unattended for years, so the contract has to be explicit,
stable and safe to retry. The plan (§6, §8) names the standards: URL-segment versions, OpenAPI with a Swagger UI that
signs in with client credentials, RFC 9457 problem details, RFC 8288 `Link` headers, the IETF `Idempotency-Key`
header and a fixed-window rate limit per client.

## Decision

- **Versions.** `Asp.Versioning` with the version in the URL (`/v1/...`) and `api-supported-versions` on every
  response. A retired version will announce itself with RFC 9745 `Deprecation` and `Sunset` headers.
- **OpenAPI.** The document is generated by ASP.NET Core's own `Microsoft.AspNetCore.OpenApi` (OpenAPI 3.1, from the
  controllers' XML comments and response metadata) with one document per version at `/openapi/v1.json`, instead of
  Swashbuckle's generator named in the plan: it is the framework's supported path from .NET 9 on and keeps up with
  new framework versions. Swashbuckle's UI is kept for `/swagger`, because its OAuth support signs in with client
  credentials against WSO2's token endpoint (`Wso2Options.TokenEndpoint`), pre-filled with the read-only demo client
  (`Api:Swagger:ClientId`, `regreturns-demo-api`).
  The document and the UI are public; every operation still needs a token.
- **Errors.** Every error is `application/problem+json` with `traceId` and, for refused use cases, the stable error
  `code` (`Submission.NotEditable`). Status follows the meaning: 400 malformed request, 401 no or bad token, 403 a
  scope or client set-up is missing, 404 not found or not yours, 409 the state does not allow it, 422 the content
  breaks a rule, 429 too many requests.
- **Paging.** `page` (from 1) and `pageSize` (default 25, at most 100). The body carries `items`, `page`,
  `pageSize`, `totalCount` and `totalPages`; a `Link` header gives `first`, `prev`, `next` and `last`.
- **Idempotency.** `POST` endpoints require `Idempotency-Key` (1 to 255 visible ASCII characters). The first request
  with a key is recorded per client with a SHA-256 fingerprint of its method, path and body, and its response is kept
  for 24 hours. A retry with the same key and body gets the stored response again with `Idempotent-Replayed: true`;
  the same key with a different body is 422; a retry while the first request is still running is 409 with
  `Retry-After: 2`. Only answers a retry should get again are stored: a 403 (the client's set-up, which an
  administrator can fix), a 409 (busy or a concurrent change), a 429 and any 5xx release the key instead, so the
  client's retry runs the request afresh. A claim whose request stopped
  without an answer (the process ended) is taken over after `Api:Idempotency:InFlightSeconds` (60). Keys are checked
  before the body is read, the body is read at most 1 MiB (413 beyond), and the key is scoped to the client, so two
  banks can use the same key. Records live in `api.IdempotencyRecords`, are written on their own connection (never
  audited: the change they guard is) and are purged hourly (`Api:Idempotency`).
- **Rate limits.** A fixed window per client id (`Api:RateLimit:PermitLimit` requests per
  `Api:RateLimit:WindowSeconds`, default 120 per minute), applied to the API's controllers only. The limiter runs
  after authentication, so a caller without a valid token is limited by its IP address instead. A refusal is 429
  with `Retry-After` and code `RateLimit.Exceeded`, and is logged; health checks, Swagger UI and the OpenAPI document
  are not limited.
- **JSON.** camelCase names, enums as strings. A delivered value is a string, a JSON number (kept exactly as
  written, never through a binary floating-point value), `true`, `false` or `null`, keyed by field code; an object
  or an array is a 400 naming the field (`values.LCR`).
- **Locations.** A new draft answers 201 with `Location` pointing at `GET /v1/submissions/{id}`; an update of the
  open return answers 200.

## Consequences

- Clients can retry any `POST` safely after a timeout, and replays are visible in logs and metrics.
- Swagger UI calls WSO2's token endpoint from the browser, so IamBootstrap adds the API's origin to the demo
  client's allowed origins.
- A rate limit kept in memory is per API instance; scaling out to several instances needs a shared store (backlog,
  the plan runs one instance).
- MVC's `[Produces]` filter overwrites the content type of every object result, problem details included, so the
  controllers declare `application/json` per success response (`ProducesResponseType`) instead, and actions refuse a
  request with `this.InvalidRequest()` rather than `ValidationProblem()`, which leaves the `code` out.
